# Prompt presets

Prompts of a house style that people pick from and that the assistant receives as examples (`examples` on the assistant calls, see [ASSISTANT.md](ASSISTANT.md)). The server keeps them; a dashboard lists and searches them with `GET /api/prompts` (see [http-api.md](http-api.md)).

## Where they live

One row of the server's database per preset (see [DATA_STORE.md](DATA_STORE.md)), with `kind` one of `image`, `video`, `motion`, `music`, `animation`, `model3d`. The command below writes to that database, so the presets it fetches appear in the server without a restart. Before the database they were JSON files, `<media dir>/prompts/<kind>/<id>.json` (`prompts/` beside the projects directory when there is no media directory): the first start imports them (`veritmo data import prompts` brings in files put there later) and leaves the files where they are. Downloads and the last report are in `prompts/.cache/` (it is not a kind, so it is never read as presets; it is safe to delete). The presets you save yourself (`POST /api/prompts`) are `own` and can be deleted; the ones that come from a bundle or from the command are bundled and read-only through the API (an import cannot be undone from the API).

## The kind `model3d`

Prompts of one object alone, for the models of the mode `models3d` ([MODEL_GENERATION.md](MODEL_GENERATION.md)): a preset is a prompt of up to 2000 characters with a title and tags, and the routes, the search, the update, the deletion and the bundles treat the kind like the others. A dashboard gives the ones a person picks to the assistant as `examples` when it writes a dataset of models or the prompt of one (see [ASSISTANT.md](ASSISTANT.md)). **There is no public source for this kind**: no set of 3D prompts has been checked for its licence, so `veritmo prompts fetch --kind model3d` says so and fetches nothing. The presets are the person's own (`POST /api/prompts`) or come in a bundle (`POST /api/prompts/import`).

## Filling the library from public datasets

```
veritmo prompts fetch [--kind kind] [--source id] [--max n] [--seed n] [--media-dir DIR] [--projects-dir DIR]
                           [--sources file] [--out file] [--dry-run]
```

It reads the sources below, writes the presets straight into the database (`--db`, the SQLite file when no other database is saved in Settings; it must be migrated: `veritmo data migrate`) and prints (and saves, in `prompts/.cache/report.md`) a report. `--out file` writes the bundle (`{format: "prompt-presets", version: 1, meta, items}`, the file `POST /api/prompts/import` takes) instead of the database; `--dry-run` downloads and reports but writes no preset and no report. Running it again adds nothing (a preset with the same kind, source and source id is already there). The media directory is `--media-dir`, else `MEDIA_DIR`, else the path in `~/.config/veritmo/media-dir`. `HF_TOKEN`, when set, is sent as a bearer token for gated files and kept nowhere.

**The licence is read, not declared.** For each source the command asks `https://huggingface.co/api/datasets/<repo>` for the dataset card and takes its `license`. A source is used only if **every** licence the card declares is in the allow-list (`cc0-1.0`, `cc-by-4.0`, `apache-2.0`, `mit`) **and** the licence the sources file expects is among them. `unknown`, a missing licence, `other`, non-commercial and share-alike licences refuse the source: the report names it with the licence it read and nothing of it is downloaded or written. A card that changes between runs is noticed. Every preset keeps its `source` (the repo) and `licence`, which is the attribution CC-BY asks for.

**What is read.** Only the files a source names and only the columns it names: the prompt, an id, tags or categories and scores. A lyrics, image or audio column is never named, so it is never loaded (the parquet reader opens the pages of the named columns only; the CSV reader scans past the others without keeping them). A parquet file is streamed: DiffusionDB's 2 million rows are never in memory together.

**What it does with a row.** It trims and collapses the whitespace, then drops (and counts, per rule, in the report) a prompt that is empty, over the source's NSFW scores (`prompt_nsfw` ≤ 0.2 and `image_nsfw` ≤ 0.5 for DiffusionDB), under 12 or over 2000 characters, only an address, with no letters once weights such as `(word:1.3)` and numbers are taken away, containing a word of a short explicit-word list (only for a source with no scores of its own), or equal to one already kept once compared with no case, punctuation or double spaces. A kept row becomes a preset: `title` (the text before the first comma, or 60 characters), `tags` (the fragments after the subject, lower-cased, 2 to 30 characters, at most 12, plus the source's own categories), `kind`, `engine` (a hint), `language` (a heuristic over common Spanish words), `source`, `source_id` (the source's id or a hash of the prompt) and `licence`. Each source is then capped to `--max` (its own `max_rows` by default) with a **seeded sample** taken after cleaning, keeping the original order: the same sources, seed and rows give the same presets (`--seed`, 42 by default).

| Source | Licence read | Kind | What is read |
|---|---|---|---|
| `poloclub/diffusiondb` | cc0-1.0 | image | `metadata.parquet` (195 MB; text only: `prompt`, `image_name`, `prompt_nsfw`, `image_nsfw`; never the images); up to 10 000 |
| `Rapidata/awesome-text2video-prompts` | apache-2.0 | video | `data/train-00000-of-00001.parquet`: `Prompt`, its `Category` as a tag in words, `video_name` as id; all 198 |
| `Kukedlc/suno-ai-music-dataset` (**off**) | cc-by-4.0 | music | `metadata.csv`: `gpt_description_prompt`, `tags`, `is_instrumental`, `id`; never the lyrics |

**The Suno source is off** (the owner's decision, 2026-11-13), and **not because of its licence**: its card declares CC-BY-4.0, which the gate accepts. It is off because of where the prompts come from: they were written by Suno's users and the gate only checks what the card *says*, not that the uploader had the right to license them. A source that is off runs only when you name it (`--source suno-descriptions`), for strictly local use, never for a bundle that is shared or published. Two more candidates are in the built-in list, off, with their notes (the per-model datasets of Rapidata and `humair025/suno-audio`: their cards are not checked). To use other sources, give a file with `--sources` (the same JSON as the built-in one: `internal/promptfetch/sources.json`); a source that is going to run is checked first (its repo and files become paths and URLs).

A real run of the command (2026-11-13, seed 42, the download plus about 20 seconds of work; with the file cached, the 2 million rows are read in under a second): DiffusionDB 2 000 000 rows read, 230 016 dropped over the NSFW scores, 416 610 duplicates, 17 892 too short, 603 empty, 280 with no letters, 72 addresses; 1 334 527 kept and 10 000 chosen. Rapidata: 198 read, 1 duplicate, 197 kept. **10 197 presets** (about 4.4 MB of text; one small file each). The script this replaces counted a few hundred rows differently (for example 17 677 too short) because it measured length in UTF-16 units and the command in characters. The Parquet library is pinned to `parquet-go` v0.25.1: from v0.26 on it fails to read DiffusionDB's file (`parquet-cpp-arrow` 10, LZ4_RAW pages); do not upgrade it without running the command on that file.
