# Veritmo in detail

[← Back to the README](../README.md)

What the program is and does, end to end: the script that drives it, the modes, the animation engines, retouch, editing a video you already have, the phone page, and a worked example.
The README has the short version and the quick start; the [tutorial](TUTORIAL.md) explains the concepts step by step.

A headless Go CLI (`veritmo`) that turns a declarative `scenes.yaml` script into a narrated video — or a batch of still images — by driving native subprocess binaries: [Piper](https://github.com/rhasspy/piper) for text-to-speech, [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) (`sd`) for per-scene image generation, and `ffmpeg`/`ffprobe` for timing and assembly.

In **video mode** (the default), each scene runs: **TTS** (Piper) → **probe** (ffprobe measures the narration's duration) → **render** (`sd` renders the scene's prompt to a still image) → **clip** (ffmpeg animates that image with the scene's optional camera `motion`/`look` presets for the probed duration — or `silence_seconds` for silent scenes — and muxes in the narration or a silent track). All scene clips are then concatenated into the final video. In **images mode** (`output.mode: images` or `--mode images`), only **render** (× `variants`) and a lightweight **export** phase run, producing PNGs plus a reproducibility manifest — see `docs/IMAGE_MODE.md`. A third, independent **music mode** (`output.mode: music` or `--mode music`) turns a `tracks:` list of style prompts and optional lyrics into complete songs with [acestep.cpp](https://github.com/ServeurpersoCom/acestep.cpp) (`ace-lm` + `ace-synth`) — see `docs/MUSIC_MODE.md`. Songs can optionally be made with **HeartMuLa**, a higher-quality (and slower) generator that runs as a local .NET service (or on another machine), and is offered only when it is available. The music studio also shows every song as a waveform, picks the part of a song to repaint by dragging on it, separates a song into instruments, compares and keeps variants, lengthens a song, marks favorites, joins songs in a mixer (beat and bar magnet, crossfades, master volume and −14 LUFS normalization) and chooses a voice and a quality level.

The definition of a project lives in the database, not in the folder: editing `projects/<id>/scenes.yaml` by hand has no effect (the next run overwrites it); change it with the editor, `PUT /api/projects/{id}/config` or `veritmo project pull|push`, and run a saved project with `veritmo --project <id>` (see `docs/CLI.md`). Each scene's TTS, render, and clip output is cached independently by content hash, so re-running after editing one scene only redoes that scene's affected phases. A companion `veritmo import` subcommand converts external datasets of scenes, animated graphics or songs (JSON, or HTML embedding a `const data` array) into a ready-to-fill `scenes.yaml`, and `veritmo check` finds the deformed or drifting clips of an animated project (with an Ollama vision model if you name one, which also looks at each face enlarged) and can fix them, and `veritmo export` writes a project back as a dataset (or as a zip package) to run it in another installation.

The editor can also **describe a reference**: you upload a picture or a clip, a local vision model (through Ollama) writes the prompt that would draw it, and the new scene is generated from that text alone (the file is never handed to the generator). A clip can be one scene or **one scene per shot**. Every person in the file is age-checked first (a minor, or an age that cannot be confirmed, is refused and the file deleted) and the model's own refusals are reported, never replaced by an invented prompt — see `docs/ASSISTANT.md`. The AI helpers (the prompt assistant, describing, the quality check) can also run on **another provider**: an Ollama on another machine or any OpenAI-compatible server, registered in the dashboard's *Settings* screen (Claude and Gemini come as presets that need only a key; API keys stay on the server and are never shown again) and chosen **per task**. They all start on the local Ollama; a remote provider needs your explicit consent, tied to its address, shows a "☁ external" badge next to every button that uses it, has a cap on calls per job, and nothing ever switches provider by itself — see `docs/SERVER.md`.

**Animation** is chosen per project: Wan, AnimateDiff, MiniMax-H3 and LTX-2.3 (the last two also write an audio track, which can be kept as quiet ambience under the narration with `model_audio`). A scene can also be a **motion graphic** (an animated title, list, chart or credits whose HTML page a local model writes and Chrome draws frame by frame) and any scene can carry an **overlay** (an animated lower third drawn over its picture or clip); A scene can also come from a **Blender** file (a 3D scene rendered headless with Cycles on one NVIDIA card, with texts, colours and properties set from the `scenes.yaml`; Blender is optional and the scene is refused, with the reason, when it is missing; a model can also write the 3D scene from an idea, it can place 3D models from `.glb` files with their own animations (a character running across a rink), taken from a **library of CC0 packs** that installs on demand (`docs/MODEL_LIBRARY.md`) or **generated** from a picture or a text by an optional container (`docs/MODEL_GENERATION.md`), and it can be named in a dataset, asked for in a single `POST /api/generations` call or used as a piece of a music motion video). Motion graphics and overlays declare their entrances as a *timeline* of tracks that the editor shows as draggable bars (in a window of its own for clips longer than 4 s) and lets you retouch without asking the model again — see `docs/SCENES_YAML.md`. Controls that need a model are hidden when none is available. A whole video of that kind can follow a song: a **music motion piece** reads the song (its beats, sections and words), picks a design and a script, and draws animated typography or illustrated characters that move on the beat, with the verse appearing as it is sung — see `docs/MUSIC_MODE_MOTION.md` (blocks of HyperFrames can be imported as parts, their small pictures carried inside). A dashboard that edits a piece can ask the server for the exact pages of an edit that is not saved yet, so what it previews is what the render draws. One sentence can also be turned into the whole plan (the song's brief, the animation's choices and the parts worth having), one sentence can also be written as a whole dataset of scenes, graphics or songs (`POST /api/assist/dataset`, checked by the import before it is returned), with prompt presets kept and searched by the server (`/api/prompts`, filled from public datasets whose licence is read from their card by `veritmo prompts fetch`: see `docs/PROMPT_PRESETS.md`) and sent to the assistant as style examples, and the assistant that writes a proposal or a part draft can be chosen per call (another provider, with consent when it is remote) — see `docs/ASSISTANT.md`.

**Retouch:** a picture of yours can be edited by an instruction ("put a red cap on him") instead of redrawn. Two engines, both installed from the *Retouch* tab of Models: **Fast** (FLUX.1 Kontext, about 40 s on a 12 GB card, non-commercial licence) and **Precise** (Qwen-Image-Edit, about 2 min, Apache 2.0). It is a look of a project, of the *Create* page and of the scene editor, and it only applies when you pick it.

**Edit a video you already have:** seven tools, each with one request and no project: **scale** it (with a super-resolution network, Real-ESRGAN, when installed), raise its **frame rate** (RIFE), **reframe** it to another aspect ratio (the crop follows the person), **remove the background** (a colour, or a WebM with transparency), make its **depth** map, **extend** it (a new clip that starts at its last frame, made with MiniMax H3 or LTX 2.3) and **move the movement of the people of a video onto another picture** (*motion control*, Wan 2.1 VACE 1.3B, about 5 minutes for 2 seconds, soft and made for people), optionally from a **library of motions** you build from videos you own. The person mask and the depth run on the CPU in a small service of their own, so they take nothing from the cards (its source ships with the private edition only; without it those tools are listed as unavailable, with the reason). Every tool says why it is not available when it is not (a missing model, a stopped service, a card too small) and falls back to ffmpeg, saying so, when its network is not installed. See [docs/VIDEO_EDIT.md](VIDEO_EDIT.md).

**From a phone:** the *Create* page (the first one of the menu, and the one a phone opens at the root address) is made for a thumb: choose what to make (video, image or song, or let the AI decide: choosing saves a call to the assistant), say or write what you want (**Improve with AI** rewrites it with more detail, in your language), check what was understood, pick a resolution level (draft by default on a phone), and see the video, image or song when it is done; a finished picture has an **Edit** button to retouch the result, and **Clear screen** empties the list (nothing is deleted). On a narrow screen the interface starts in a **simple version** with only Create and Gallery (a switch in the menu goes to the advanced one; the API reference and the settings never open on a phone). A photo taken on the spot can be **retouched by instruction** ("ponle el pelo rubio al chico de la izquierda"): the assistant rewrites it, in any language, as a short English instruction for the editing model, which you can read and correct. For a song you pick the generator (ACE-Step, HeartMuLa or DiffRhythm2: each is asked for the style words it reads, with tags chosen from a vocabulary and ten popular combinations a tap away, and lyrics sized to the length you pick), edit the suggestion before confirming, and can hold the phone to a speaker so the server **recognises the kind of a song that is playing** and writes a new original one like it (its tempo, key and theme; the lyrics heard are never kept). The voice is read on your own server (Whisper, on the CPU); the browser only gives the microphone to a secure page, so serve the dashboard over HTTPS — see `docs/SERVER.md` ("HTTPS for the microphone"). Over HTTPS the dashboard can also be **installed as an app** on Android and iOS (`docs/SERVER.md`, "Install it as an app on a phone").

The dashboard starts in English; the *English / Español* switch at the bottom of the side menu changes it (the choice is remembered in the browser).

New here? **[docs/TUTORIAL.md](TUTORIAL.md)** explains the concepts, the same things from the terminal and a complete worked example ([also in Spanish](TUTORIAL.es.md)). The step-by-step guide to the dashboard, with annotated screenshots, lives with the dashboard (the `dashboards-lab` project).

## An example

A 30-second clip made entirely with the orchestrator: two cats in karate suits who bow, spar and bow again in a dojo. It is 15 scenes of a `scenes.yaml` (one still picture per scene, animated with MiniMax-H3 using the picture as the first frame and its 8-step LoRA, about 3 minutes per scene on a 16 GB card, 48 minutes in all). The whole file is docs/examples/cats-karate.scenes.yaml; `defaults.subject_prompt` describes the two cats and the dojo once and is prepended to every scene, so they look the same in every cut, and each scene only says what its shot shows and what moves:

```yaml
defaults:
  subject_prompt: >-
    photo of an orange tabby cat in a white karate gi with a black belt and a grey tuxedo cat in a black
    karate gi with a red belt, both standing upright on two legs like martial artists, detailed fur,
    traditional wooden dojo, tatami mats, paper screens, warm sunlight through the windows, cinematic, 35mm,
  animate:
    engine: minimax-h3
    first_frame: true        # the scene's picture is the first frame of the clip
    diffusion_model: models/video/minimax_h3_fl2va_pruned-Q4_K_M.gguf
    llm: models/video/qwen3vl_32b_minimax_h3-Q4_K_M.gguf
    vae: models/video/minimax_h3_video_vae_fp16.safetensors
    audio_vae: models/video/minimax_h3_audio_vae_fp32.safetensors
    lora: models/video/minimax_h3_fl2v_turbo_8step.safetensors   # 8 steps
scenes:
  - id: s07_roundhouse
    seed: 207
    silence_seconds: 2
    animate: true
    prompt: wide shot, the grey cat throwing a high roundhouse kick while the orange cat ducks
    motion_prompt: the grey cat swings a high roundhouse kick, the orange cat ducks under it, static camera
```

The clip itself is on the [examples site](https://veritmo.xuxo.net/) and at the top of the README of the public repository.

This behavior is specified in detail in `openspec/specs/` (one capability per `internal/` package, plus `scene-import`, `export` and the management server and dashboard); the documents listed below are derived from those specs.

> **This repository is the server only:** the API, its access token and its security. The dashboards live in the `dashboards-labs` repository (the management app is moving there as `dashboard-full`), and the server serves any built front end from a folder with `veritmo serve --web-dir <folder>` (see [docs/SERVER.md](SERVER.md#a-front-end-from-a-folder---web-dir)). `./serve.sh` starts only the server, and the binary has no front end inside.
